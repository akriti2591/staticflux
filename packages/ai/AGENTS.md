# @staticflux/ai — AGENTS.md

**Layer:** vertical (depends only on `@staticflux/core`). Adapter package: browser AI APIs are experimental, so they live here and never in core (R19.15).
**Budget (proposed):** ≤ 5 KB brotli minified; lazy (never in the boot bundle).

## Purpose
One **model provider** port (R19.17) over browser built-in AI (Prompt / Summarizer / Translator /
Language Detector), decision models (Jev-like: closed options → probabilities), remote LLMs and a
mock. Availability (incl. download state and progress) is a reactive fact per task.
**AI is never on the critical path:** every call is async, cancellable, returns a `Result`, and
features must have a non-AI fallback.

## Public API (by file)
- `provider.ts` — `ModelProvider` (`facts`, `probe`, `prepare(task, { onProgress, languages })`, `generate`, `summarize`, `translate`, `detectLanguage`, `decide`, `dispose`), request/result types, `AI_TASKS`, `classify`, `availabilityMachine` (`ai/model-availability`), `createAiFactsStore`, `AiMetrics`, `instrument`, `mapAiError`.
- `browser.ts` — `createBrowserAiProvider({ globals, probeLanguages, telemetry })`, `detectBuiltInAi(globals)`; structural shapes of the Chrome APIs (`availability()` states, `create({ monitor })` with `downloadprogress`); legacy `self.ai.*` / `capabilities()` accepted.
- `decision-model.ts` — `createDecisionModelProvider({ id, model, transport })`, `DecisionModelTransport` port, `validateDecision`, prompt-based `promptDecide` / `promptDetectLanguage` (JSON-schema constrained).
- `remote.ts` — `createRemoteLlmProvider({ id, transport, tasks })`, `RemoteLlmTransport` port (the transport owns auth/endpoint, e.g. BFF or host bridge).
- `mock.ts` — `createMockProvider(options)` (scripted availability, simulated download progress, call log).
- `router.ts` — `createModelRouter({ providers })`: routes per task (available → downloading → unknown), falls through on SF-AI-001, merged reactive facts.
- `units.ts` — `ModelProviderToken` (router), `ModelProvidersToken` (multi), `aiUnits`, `browserAiProviderUnit`, `modelRouterUnit` (background probe in `init`), `modelProviderContribution`, `mockModelProviderUnit`.
- `errors.ts` — `SF-AI-001` unavailable … `SF-AI-005` invalid model output.

## Semantics
- Requests never start a download implicitly: `downloadable` → SF-AI-001 with a hint; call `prepare(task)` from a user gesture (Chrome needs user activation → otherwise SF-AI-002).
- `translate` availability is per language pair: the fact stays `unknown` unless `probeLanguages` is configured.
- `decide` output is validated against the closed options and normalized; usable directly as the advisors' `DecisionModelPort`.

## Lifecycle (mirror into docs/LIFECYCLES.md §14)
`ai/model-availability`: unknown → probing → unavailable | downloadable | downloading | available; downloadable → downloading → available | downloadable (aborted / no gesture) | unavailable; settled states → probing.
(Overlaps `platform/ai-probe`; platform keeps the boot-time presence fact, this package owns per-provider runtime state.)

## Rules
- Feature-detect everything; Safari/Firefox have none of these APIs — missing = `unavailable`, never a thrown error.
- Never put AI output on a correctness path without validation (structured output is parsed and checked).
- Send remote models only what the feature declared.
