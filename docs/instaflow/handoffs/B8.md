## Decisions (and why)
- **Placement:** editor and render modules run in one realm (main thread) on the `local` medium, behind A7's ports. B3, B6
  and B2's TextInput need the DOM; the stage and tools do not cross a worker boundary yet. D15's one-worker default with
  the modules in the pipeline worker is a follow-up (IF-27.4).
- **Overlay in the content scene:** the render engine's canvas is opaque (`gpu.rs` `CompositeAlphaMode::Opaque`), so B3's
  overlay draws into the same scene under ids from `0x4000_0001` (`toolOverlayBatch(..., { clear: false, ids })`). The
  raster background is white (the page colour); the page edge is an overlay line.
- **Text** is not a projection kind: the text layer emits B2 glyph groups (odd scene ids) on the record's IR section, above
  the page's other elements; box size (`spatial.w/h`) is written with each edit in the same change set.
- **IME finding 2:** I could not reproduce the exact growth without the owner's CJK fonts; the mechanism was that control
  bounds came from the composition *preview* layout (it grows when the preview wraps or its fallback fonts change line
  metrics). They now come from the committed block (`text-session.ts`); `text-session.ime.test.ts` fails on the old code.
- Spec schema: HUD up to 48 actions (was 12) since `more` actions collapse into one menu. Properties placeholder no longer in
  Studio's tables (the real inspectors replace it).
- Shortcut registry (framework): an EditContext host counts as a typing field (Studio's tool letters stole typed keys).
