## Decisions (and why)
- **One model field, `spatial.skewX`** (degrees; box linear = rotation · flips and scale · skew). Any 2D affine fits, so
  every transform is written by decomposing a page affine (`valuesForTransform`); a vertical skew becomes rotation + skew
  + size. Additive component change (no version bump); position locks cover it (app stage rules). B1's transform keeps
  its exact terms without skew (goldens unchanged).
- One element flips and skews **along its own axes** (rotation kept, `flipX` toggles); several along the page axes.
- The decomposition picks the flip that keeps the rotation closest to the old one (a flip stays a flip, not 180° + flipY).
- **Pivot** = selection-frame fractions in `ViewState` (never the document), reset when the selected set changes; shown in
  transform mode or once moved. Resize handles win over it, except with Alt (a pivot snapped to a corner is still reachable).
- **Mod on a side handle now skews** (B3: Mod meant "resize without snapping"); corners keep B3's meaning.
- **Transform mode** = a session over B3's session layer: steps stage previews (`SINKS`, `APPLY` tables, no mode branches);
  Enter / Apply / a new selected set commit one change set; Escape / Cancel / Undo / page switch cancel. Enter and Escape
  get their meaning from a child shortcut scope active only during a session. A press outside the frame rotates.
- A session stages only fields that differ from its base, so an agent's commit during a session is not hidden.
- **Mod+T is reserved by browsers** outside full screen / installed apps: Free transform is also a HUD action (`more`).
- Bar values: one element = its box in its parent (like B1's inspector); several = their frame on the page.
- `@instaflow/app/tools` budget 24 → 27.5 KB (reason in the entry name); new entry `@instaflow/app/tools/transform-bar` (2.5 KB).
