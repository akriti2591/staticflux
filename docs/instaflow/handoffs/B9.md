## Map: what B8 runs on main (all of it) and where it goes
| Piece (B8 file) | B9 home | Main keeps |
|---|---|---|
| Document peer, stage, undo, repeat view, brand kit (`document.ts`) | editor module (worker) | — |
| Store + blobs + library document + library services (`document.ts`, `studio-app.ts`) | **main, as the store-worker stand-in** (ARCHITECTURE §2: the store worker owns storage, blobs and the library doc; C0 brings the real one) | served to the editor over a store port (`DocumentStore` + blob reads) |
| B3 view state, index, tool session, controller, snapping, creation tools, commands, overlay (`canvas-tab.ts`, `creation.ts`) | editor module | the canvas tool shortcuts stay *registered* on main (preventDefault, help list); their handlers run in the worker |
| B2 text layer (layout, glyph IR) and text session (`text-layer.ts`, `text-editing.ts`) | editor module | EditContext / textarea `TextInput` on a host div; a TextInput **port** carries intents in and caret, selection, character and control bounds out (surface px; main adds the surface offset) |
| B6 projector + announcer (`canvas-a11y.ts`) | editor module (`createCanvasProjector`) | `mountCanvasA11y` applies posted snapshots; focus → `select` intent; the live region |
| B1 publisher, A7 render module, element port, Vello raster (`canvas-pipeline.ts`, `element-port.ts`, `vello-raster.ts`) | publisher: editor module; render module + Vello on a transferred **OffscreenCanvas**: render module | nothing (no main raster) |
| B3 overlay (drawn straight into the raster in B8) | an IR section of the same scene record as the content it frames (same frame, E-2) | distance labels (kit tags) from a posted projection |
| Capability implementations (B1, B7, B3, B6, B5) | editor module | the registry (validate, gate) with forwarding implementations |
| Panels: appearance, repeat, typography, milestones, save status, story (Pages reorder) | services in the editor module | panel elements over **mirrors** (reactive reads posted from the worker, actions forwarded) |
| Lens controller (Pages panel navigation) | main (a panel model over a mirrored structure feed: decides only which page the canvas shows, then asks the editor) | yes |
| Versioning (Latest, milestones, capture) | editor module (capture reads the live parts; writes go to the store port) | mirrored panel model + save status |
| Pointer / wheel / keys | input forwarder → A5 input ring → editor module | yes (capture only) |

## Decisions (and why)
- Store side stays on main as the store-worker stand-in (see the table); the editor never writes storage directly.
- Lens controller on main: it holds navigation state only; the camera port is a no-op in M1 as in B8.
- Sync panel actions (`Result` returns) are answered optimistically across the boundary; failures are announced politely.
