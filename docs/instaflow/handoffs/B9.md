## Decisions (and why)
- Store side on main (store worker owns storage, blobs, library doc; C0 brings it); editor never holds a store.
- Versioning lives with the doc in the editor; `MilestonesPanelPort` (B5) narrows what the panel reads to plain outcomes.
- Lens controller stays on main (navigation model over the mirrored structure; camera port still a no-op).
- Overlay goes in the scene record (format 2: resources, assets, **image table**, projection, IR, **overlay**), so it is
  drawn in the same frame as the content; image ids cross in the table (render side encodes images).
- Panels over **mirrors** (`defineMirror`); sync panel actions answer `ok` optimistically, failures are announced.
- Canvas shortcuts: same defs registered on main with no-op handlers (default prevented, help, scope as B8); run in the
  editor from ring keys. TextInput port: a state is applied on main only with no intent in flight.
- Editor publishes on a microtask (draw on arrival); a11y projections on the worker's rAF. Dev server sends COOP/COEP.
- Fixes owed to integration (each tested): text hit across its box (B1 `hitElement`), Studio spec changes serialized (B0:
  a lens switch racing a scope change restored a stale scope), stray pointer-up after double click not an error,
  `user-select`/`touch-action: none` + no `dragstart` on the surface (native drag fired `pointercancel`), lens controller
  starts on the shown page, main asks the editor to repost after subscribing (`sync`).
- Framework: `@staticflux/a11y` shortcut `isEditable` works without DOM; `@staticflux/ui/theme` takes `unsafeCSS` from
  `@lit/reactive-element/css-tag.js` (peer + dev dep, lockfile) so themes load in workers. No new R-IDs.
- Lit-free splits for the worker graph: `elements/capabilities.ts`, `repeat/capabilities.ts`, `text/commands.ts`,
  `spec/studio-ids.ts`, `a11y/describe.ts` + `a11y/editor-side.ts`, `tools/overlay-labels.ts` (old paths re-export).
