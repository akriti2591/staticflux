## How B11b uses them
- **Boot:** register `INSTAFLOW_SURFACE_UNITS` (instead of `messagingUnits`) with `localSeenStore(localStorage)` bound to `SeenStoreToken`;
  mount one `<sf-surface-layer>` per surface; bind `ToastsToken` with `createToasts(manager, ownerOf(appInjector))`; Home binds `Mod+Z` →
  `toasts.undoNewest()`. Set `--sf-toast-offset` on Studio to sit 16 px above the command bar.
- **HUD per kind:** declare each kind's set with `defineControls` (§4.2.4 table; ranks are slots); the pill renders `hudControls`, the
  inspector `inspectorSections(set, density)` with `<sf-disclosure variant="more" .count>` for `more`, `pinned` in Pro. Mark the pill root
  `data-sf-overlay="hud"` and `role="toolbar"`. Swatch → `<sf-popover outside="pass" .anchor=${item} .returnFallback=${canvas}>` holding
  `<sf-color-popover>` (`custom-open` + `captions` in Pro); `Font ▾` → `<sf-font-picker>` (preview on `sf-preview`, commit one undo step on
  `sf-change`); `Align ▾` → `<sf-align-popover .count>`. Choice ▾ items are `<sf-menu>` (allowed: hud → menu). More `⋯` = `<sf-menu filterable>`.
  Pro tooltips: pass `description`; bottom bars and the HUD set `tooltip-side="block-start"`.
- **Context menu:** `bindContextMenu(canvasEl, menu, signal)`; use `<sf-menu-group>` and submenus (`Select same ▾`, `Align ▾` …, STUDIO §8.1).
- **Share / Milestones dialogs:** `defineDialogSurface({ size: 'wizard' })` with the frame's `step`/`steps`/`dirty` and `sf-back`; link row =
  `<sf-copy-field>`; access row = two `<sf-menu>`; remove person / delete milestone = `<sf-confirm-row>`; preview / Compare =
  `<sf-takeover heading meta back-label>` in a dialog surface; worker crash = `<sf-banner>` then `defineBlockingErrorSurface` with `replace`.
- **Routes (overlay-side hooks):** routable dialogs keep using messaging's `createRoutableDialogBridge`; `handle.dismiss` reasons and the
  frame's guard already distinguish Back (`sf-back`) from Escape; a deep-linked arrival calls `hintSession.suppress()`.
- **Hints:** mark targets with `coachTarget(HintTargets.frameTool)` etc.; `offer` on first hover/selection of the tool, `used` on first use.

## Decisions (and why)
- **Submenus are a sibling** `<sf-menu slot="submenu">` after their row, not a child: a child would nest menuitems inside a menuitem (APG and
  the audit's nested-interactive rule).
- **No global overlay registry** (rule 2): sessions talk through `sf-overlay-open/close` document events; parents are found in the flat tree.
- Messaging keeps its **default (queueing) policy**; the strict policy is opt-in so `apps/studio` and existing tests are unchanged.
- Chrome popovers default to `outside="consume"` (spec §1.4); HUD/inspector pass `pass`. Popovers no longer focus their panel when nothing
  inside is focusable (§1.3).
- Tooltip and icon-button tooltips default **below** the anchor (§4); `sf-surface-layer` tooltips unchanged.
- Kit strings stay American (B11a); new strings live in two catalogs (`feedbackMessages`, `pickerMessages`) so small controls do not pay.
- Clean Pop Pro spacing stays on the 4 px grid (the theme contract) where DENSITY §6 asks 6 / 10 px. The tooltip `description` line is shown
  when passed: the HUD projection passes it only in Pro (components read tokens, not the mode).
- The control model is Instaflow (`src/spec/controls.ts`, FOUNDATIONS §6 places it there): types and projections only.
- Section errors (mist card in a panel) reuse shell `<sf-boundary>`; no new kit element.
