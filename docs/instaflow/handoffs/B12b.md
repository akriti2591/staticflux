## Scope status
- **P1, stale caret after an editor caret move: done.** Root cause: main's EditContext learns the editor's caret only from
  the editor's next `state`; a key or composition typed within that round trip carries main's old range, and the editor applied
  it literally ("Hello 日本語Studio"). Fix (`workers/text-port.ts` only; the session and `@staticflux/surface` are unchanged):
  states carry a `version`, main stamps each intent with the version it last applied (`base`). The editor keeps the states it
  posted, rebuilds main's view (state `base` + main's own local edits since, through `applyTextIntent`; the hidden textarea
  applies only compositions locally) and, when it differs from the editor's current state, `rebaseIntent` moves an insert, a
  composition start or a delete **at main's caret** onto the editor's selection; other ranges map through the text change
  (`textOffsetMap`). A rebased composition's character bounds cross shifted by the composition offset. The next state resyncs.
- **P2, text outside the element tree: done.** Root cause: text was not a projection kind; the text layer appended its glyph
  groups at the scene root with page transforms, so they painted above all shapes and outside clips, masks and group looks. Fix:
  `text` is a kind of `ElementProjection` (version 2; a group look with the element's effects, no paints), and the text layer
  draws each glyph group under its element's scene node (`sceneParent: projectedSceneId(projector)`), in local space (only the
  fixed box's vertical-align offset). The INT-9 layer look moved from the text group to the element node (`textSceneNodes` lost
  its `layer` option). Export `sceneIds` is now the projected ids (the node draws its text).
- **Found while building P2:** the render side encodes the store's *final* state and then replays every queued IR batch, so a
  text element edited and then deleted within one render frame replayed an upsert under a node the element batch had already
  removed: the Rust scene failed the whole batch ("unknown parent", one draw failure). `ir.rs` now drops an `UPSERT` under a
  missing parent, as it drops a `REMOVE` of an unknown id; cycles still fail.

## Decisions (and why)
- Rebase, not reject: the editor's selection is what the person sees (it draws the caret), so an intent at main's caret means
  "at my caret". Rejecting would drop a keystroke. Only caret-anchored ranges move; other ranges map, so autocorrect still works.
- The version lives on the app's port messages, not in the framework `TextInput` port: no framework API change, no R-ID.
- Text projects as a *group look*, so the existing encoder, draw traversal and exporters needed no new geometry kind.
- `ir.rs` leniency instead of encoding per record: per-record encoding would multiply the O(n) diff per frame during drags.
